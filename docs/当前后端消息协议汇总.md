## 2. GateServer HTTP 消息

```text
Content-Type: application/json
```

GateServer 回包的错误字段叫：

```json
{
  "error": 0,
  "message": "success"
}
```

## 3. ChatServer WebSocket 握手

客户端使用登录回包里的 `host` 和 `port` 建立连接：

```text
ws://127.0.0.1:7891/
```

必须携带：

```http
Authorization: Bearer b78007f688a2aaae183976e9f9294e9b448398504094f23523c4e9f532f8ff03
X-User-Id: 3
X-Device-Id: 10001
```

成功：

```http
101 Switching Protocols
```

缺少认证信息：

```http
401 Unauthorized
Content-Type: text/plain; charset=utf-8

Missing authentication headers
```

Token 或登录会话无效：

```http
401 Unauthorized
Content-Type: text/plain; charset=utf-8

Authentication failed
```

## 4. ChatServer WebSocket 通用格式

### 4.1 客户端请求格式

```json
{
  "version": 1,
  "require": "业务路由",
  "request_id": "客户端请求ID",
  "data": {}
}
```

部分业务还会增加：

```json
{
  "action": "具体动作"
}
```

### 4.2 服务端回包格式

```json
{
  "version": 1,
  "type": "业务回包类型",
  "request_id": "客户端请求ID",
  "error_code": 0,
  "message": "给人看的消息",
  "data": {}
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `version` | integer | 当前为 1 |
| `type` | string | 回包或推送类型 |
| `request_id` | string | 对应客户端请求 |
| `error_code` | integer | 客户端业务判断依据 |
| `message` | string | 显示和日志使用，不能作为程序判断依据 |
| `data` | object | 业务数据，没有数据时可能省略 |

### 5.2 使用 URL 上传文件 ✅

这一步不是 WebSocket JSON。客户端直接把二进制 PUT 到 `upload_url`：

```http

Content-Type: image/png

<图片原始二进制>
```

客户端必须原样携带 `upload_headers`，不能使用 `form-data`，不能重新拼接 URL。

### 5.4 FileServer 临时异常：只重试 Complete ⬜

适用情况：

- ChatServer 无法连接 FileServer；
- FileServer 超时；
- FileServer 返回不完整响应；
- FileServer 返回内部错误；
- MinIO 暂时不可用。

回包：

```json
{
  "version": 1,
  "type": "set_avatar_ack",
  "request_id": "avatar-complete-001",
  "error_code": 4001,
  "message": "file service is temporarily unavailable",
  "data": {
    "session_id": "avatar/3/83cbd209-b75c-4f24-bbcc-b12fa89940ff.png",

    "retry_after_ms": 1000

```

客户端行为：

```text

不重新 PUT 文件
```

## 6. 上传恢复动作

客户端不要根据 `message` 猜测是重试还是重传，统一读取：

```json
{
  "recovery_action": "retry_complete_upload"
}
```

| `recovery_action` | 客户端处理 |
|---|---|
| `none` | 不自动恢复，显示错误或等待用户操作 |
| `retry_complete_upload` | 保留文件和 Session，只重试 `completeUpload` |
| `restart_upload` | 重新 `initUpload`，重新 PUT 文件，再 Complete |
| `reauthenticate` | 重新登录或刷新登录状态 |

推荐客户端重试间隔：

```text
第 1 次：1 秒
第 2 次：2 秒
第 3 次：4 秒
```

达到最大次数后停止自动重试，保留 Session，让用户稍后手动重试。只有服务端返回 `restart_upload` 时才重新传文件。

## 9. 用户资料更新推送 ⬜

头像写入 MySQL、增加 `profile_version` 并完成 Redis `ready` 后，ChatServer 主动推送：

```json
{
  "version": 1,
  "type": "user_profile_updated",
  "data": {
    "uid": "3",
    "changed_fields": [
      "avatar"
    ],
    "avatar_file_id": "avatar/3/83cbd209-b75c-4f24-bbcc-b12fa89940ff.png",
    "profile_version": 12
  }
}
```

客户端处理：

```text
如果推送中的 profile_version > 本地 profile_version：
    接受更新
    保存新的 avatar_file_id
    重新申请头像下载 URL
否则：
    丢弃重复或乱序推送
```

推送中不发送永久头像 URL，因为 MinIO 下载 URL 会过期。

当前 `ConnectionMgr` 尚未建立 `uid -> 多设备连接` 索引，该推送还未实现。

## 10. ChatServer 当前错误码

|---:|---|---|

| 2012 | `Mysql_Result_Error` | MySQL 结果异常 |
| 3001 | `Redis_Error` | Redis 错误 |
| 3002 | `Conversation_Not_Exist` | 会话不存在 |
| 4001 | `File_Rpc_Error` | 无法正常调用 FileServer |
| 4002 | `File_Request_Error` | FileServer 响应或业务请求错误 |

| 4004 | `Upload_Session_Invalid` | 上传 Session 数据无效 |
| 4005 | `Upload_Session_Expired` | 上传 Session 过期 |

| 4007 | `Upload_Metadata_Mismatch` | 上传对象元数据不一致 |
