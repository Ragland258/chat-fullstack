# 前后端网络请求与中文乱码问题

## 现象

- GateServer 未监听 `9999` 端口时，注册页面只显示“网络请求失败”。
- GateServer 正常运行时，请求能够成功，但验证码成功提示显示乱码。
- 从不同工作目录启动后端可执行文件时，可能找不到 `config.ini` 并直接退出。

## 原因

1. 后端原先只从当前工作目录读取 `config.ini`，启动目录变化会导致配置加载失败。
2. 后端部分源码使用 GBK 保存，却把 JSON 响应声明为 UTF-8，中文消息字节因此被前端错误解码。
3. 前端丢弃了 `QNetworkReply::errorString()`，页面只能显示笼统的网络错误。

## 修复

- `ConfigMgr` 优先从可执行文件目录读取配置，并保留当前工作目录作为回退路径。
- Visual Studio 构建完成后把现有 `config.ini` 复制到输出目录，不修改配置内容。
- 前端根据稳定的业务错误码显示本地 UTF-8 中文消息，避免依赖后端错误编码的文本。
- 网络失败时记录 URL、HTTP 状态码和 Qt 错误信息，并把具体错误显示到页面。

## 验证

- 2026-07-30：VS2022 x64 Debug 编译通过，0 个错误；构建后 `config.ini` 已复制到后端输出目录。
- 2026-07-30：以 `D:\Tools` 为工作目录启动 GateServer，日志显示从 `D:\build\chat\x64\Debug\config.ini` 加载配置，并成功监听 `0.0.0.0:9999`。
- 2026-07-30：Qt 6.10.1 MinGW Debug 编译通过；自动进入注册页并获取验证码，GateServer 收到 `POST /get_verify`，界面显示“验证码发送成功”。
- 2026-07-30：停止 GateServer 后重新请求，界面显示“网络请求失败：Connection refused”。

## 遗留事项

- 后端仍有部分 GBK 源文件。后续可单独安排一次编码迁移，将源码统一为 UTF-8，并在编译器中固定源字符集。
