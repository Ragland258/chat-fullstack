# StatusServer 环境配置变更日志

日期：2026-08-03

## 变更内容

1. `StatusServer.vcxproj`
   - 删除 `<VcpkgEnableManifest>true</VcpkgEnableManifest>`：项目原本开启了 vcpkg manifest 模式，但目录下没有 `vcpkg.json`，导致编译直接报错。删除后与 `chat.vcxproj` 一致，走 vcpkg 经典模式（`D:\vcpkg\installed\x64-windows`），自动获得 grpc / protobuf / hiredis 的头文件和库。
   - 四个配置统一增加预定义宏 `_WIN32_WINNT=0x0601`。
   - 四个配置统一关闭警告 `4996;4251;4267;4819`（新版 gRPC 头文件在 v143 工具链下会触发，`chat.vcxproj` 同样处理）。
   - Release/Debug x64 增加 PostBuildEvent：自动把 `config.ini` 拷贝到输出目录。

2. `StatusServiceImpl.h`
   - 修正陈旧相对路径：`../ConfigMgr.h` → `ConfigMgr.h`、`../Const.h` → `const.h`、`../generated/message.*.pb.h` → 本目录的 `message.*.pb.h`。

3. `main.cpp`
   - 修正 `../ConfigMgr.h` → `ConfigMgr.h`。

4. `StatusServiceImpl.h`、`main.cpp` 由 GBK 转码为 UTF-8（带 BOM），中文注释不再乱码。

## 验证结果

- `Release|x64` 通过 MSBuild 编译成功（v143 / C++latest）。
- 产物：`x64\Release\StatusServer.exe`（grpc/hiredis/protobuf 等 DLL 自动拷贝）。
- 启动测试：配置加载正常，gRPC 服务监听 `127.0.0.1:50052` 与 `[::1]:50052`。
- 停止测试进程，无残留。

## 已知问题（未修复）

- `StatusServiceImpl.cpp` 的 `LoadChatServer` 读取 `config.ini` 的 `[ChatServer]` 段，但实际配置段为 `[ChatServer1]` / `[ChatServer2]`，启动日志会打印 `ChatServer Host or Port is empty`，服务器列表为空。需要 RPC 分配聊天服务器时须先修复。
- 当前本机 Redis（6379）未运行；`GetChatServer` 校验 token 依赖 Redis。
